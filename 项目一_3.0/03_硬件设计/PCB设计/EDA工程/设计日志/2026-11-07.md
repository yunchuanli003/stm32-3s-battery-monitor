## Keil 下载失败排查（已闭环）

**现象**：`Erase Done.` → `Programming Failed!` → `RDDI-DAP Error` → `Flash Download failed - "Cortex-M3"`，调试器 CMSIS-DAP。

**误判过程**：中途让用户量电压，得到 5V=2.74V / 3.3V=3.2V，一度判定"5V 轨死了、3.3V 是反灌"。随后用户说明**核心板是单独拆下来测的**——单独的核心板 5V 脚本就悬空，2.74V ≈ 3.2 − 0.46（LDO 体二极管倒灌）属正常，该结论作废。

**真因**：用 CMSIS-DAP 的 3.3V（约 100mA）给核心板供电。擦除电流小能过，写入瞬间电流冲高 → 3.3V 跌落 → SWD 链路断。

**解法（用户实测有效）**：
1. 核心板插 micro-USB 自供电
2. 调试器只留 TMS(SWDIO) / TCK(SWCLK) / GND，拔掉 3V3 和 RST
3. 下载成功：`Programming Done / Verify OK / Application running`（23:27:01）

**判据沉淀**：`Erase Done` 之后才失败 = 连接和芯片都正常，问题在**持续供电能力或 SWD 信号质量**，不在接线和芯片。此外备查：SWD 时钟降到 1MHz、Flash 算法必须是 STM32F10x Med-density 128K。

## 电机「猛转 + 糊味」定因（2026-11-07 夜）

**现象**：接 3S 电池后，长按 KEY2 / 短按进高温模拟，J2 上的电机猛转 1~2 秒即出现绝缘漆异味；断开电池只留 USB 时，同一电机转速正常、不发热、无味。

**定因**：`VM` 直连 `VBAT_F`，电机端电压完全由电池决定。
- USB 供电时 `VBAT_F ≈ 4.5V`（K7805 反灌，之前那个被判为「假读数」的值，实际就是 VM 电压）→ 电机正常
- 电池供电时 `VM = 12.6V` → 2.8 倍过压，功率约 7.8 倍 → 过热有味

**结论**：`J2` 上接的是 **5V 量级电机（130 电机额定 3~6V）**，与 12V 系统不匹配。不是电池故障，不是 D 类设计错误。

**代码改动（三处，已落盘）**：
1. `tim.c`：Prescaler 71→0、Period 999→3599，PWM **1kHz → 20kHz**（原 1kHz 落在可听频段且有明显力矩脉动）
2. `motor.h`：新增 `MOTOR_SPEED_MAX = 40`（12.6×40%≈5.0V）、`MOTOR_RAMP_INC=10`、`MOTOR_RAMP_STEP_MS=25`
3. `motor.c`：`Motor_SetSpeed` 改为读 `__HAL_TIM_GET_AUTORELOAD()` 动态算 CCR（不再写死 999），并按 `MOTOR_SPEED_MAX` 限幅；`Motor_Forward` 增加阶梯软启动
4. `main.c`：高温模拟/高速档 `100` → `MOTOR_SPEED_MAX`；低速档 `50` → `MOTOR_SPEED_MAX/2`

**根本解法（待办）**：换真正的 12V 风扇，然后把 `MOTOR_SPEED_MAX` 改回 80。当前 40% 是保护性补丁。

**重要操作顺序**：板子上跑的仍是旧固件（100%），必须先烧新固件再上电池，否则会再烧一次电机。

## 核心板接口与烧录方式（用户口述确认，2026-11-08 00:47）

野火小智 STM32F103C8T6 核心板共三个接口：

| 位置 | 接口 | 用途 |
|---|---|---|
| 一侧 | Type-C | **USB 供电**（日常用这个） |
| 另一侧 | Type-C | **串口打印**（CH340 → PA9/PA10，USART1） |
| 中间 | 5 针 SWD 座 | `3V3 / TMS / GND / TCK / RST` → 母对母线接 CMSIS-DAP 小板 |

**关键事实**：DAP 自身由 USB 供电，拔掉 DAP 的 USB 后 3V3 引脚无输出 → 五根线**可以常挂**，不需每次拆线。

**烧录流程的坑**：只插 DAP、不插供电 Type-C 时，核心板靠 DAP 的 100 mA 跑，写 Flash 掉压 → `Programming Failed / RDDI-DAP Error`（11-07 已复现）。正确做法是**烧录时把供电 Type-C 也插上**，DAP 只做信号；不放心可把 DAP 的 3V3 拔掉（五根变四根）。

**两个 Type-C 不要同时插**（等于两个 5V 源并在核心板上）。

## 双接（电池 + USB）的真实结论

| 状态 | VBAT_F | 反灌 | 5V 源 |
|---|---|---|---|
| 只 USB | 4.52 V | 发生 | USB 一路 |
| 电池 + USB | 11.3 V（电池主导） | **不发生** | 两路并联，谁高谁供 |

- 电池在时 5 V 顶不过 11.3 V，反灌路径不通，**OLED 电压读数是准的**
- 风扇走 VM（电池侧），**不占 USB 的 500 mA 配额**（此前判断有误，已纠正）
- 双接只有三条边界：别挂几小时；WiFi 满负荷时留意 ~400 mA；调试器 3V3 永远不留

## D1 不是 ORing

`D1(SS34)` 位于 `J1 → VBAT_F` 之间，只挡电池接反。反灌路径是 `USB → 核心板 5V 脚 → 板上 +5V 网络 → 穿过 K7805 → VBAT_F`，**完全绕开 D1**。真正的 ORing 要在 +5V 网络上两路各串一个二极管，板上没有 → 定案：不改板，靠 SOP 管控。
