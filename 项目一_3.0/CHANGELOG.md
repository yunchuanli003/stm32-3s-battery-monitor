## [3.0.3] - 2026-11-14

> 清掉主循环里最后一段阻塞：报警蜂鸣从「响完才返回」改成「排节目 + 节拍推进」。

### 🐛 修复
- **`Alarm_Update()` 不再阻塞**。原来过压/欠压分支是 `BEEP=1; HAL_Delay(100); BEEP=0; HAL_Delay(80); BEEP=1; HAL_Delay(100); BEEP=0;`，一口气把主循环卡死 **280 ms**；高温分支卡 100 ms。这就是「报警那一秒画面卡一下」的来源
- **新增蜂鸣器节拍器**：`BeepStep_t {on, off}` 表 + `Beep_Play()` / `Beep_Task()`，主循环每轮调一次，时间到了才翻一次电平，其余时间立刻返回。阻塞时间 **0 ms**
- **`Key_Beep()` 一并非阻塞化**：短按 50 ms、长按 50+60+50 原来是死等，按键时画面会顿一下；现在同样走节拍器
- **优先级规则**：报警 `Beep_Play` 会打断正在播的按键音（报警比按键反馈重要）；按键音不会打断报警，因为报警每秒会重新起播

### 🔧 表结构
```c
PAT_ALARM_VOLT[] = {{100,80}, {100,0}, {0,0}}   // 双短音（电压越限）
PAT_ALARM_TEMP[] = {{100, 0},         {0,0}}   // 单短音（高温）
PAT_KEY1[]       = {{ 50, 0},         {0,0}}   // 按键 1 声
PAT_KEY2[]       = {{ 50,60}, { 50,0}, {0,0}}  // 按键 2 声
```
`off == 0` 是**结束标记**，不是"停 0 毫秒"。写成 `{100,80},{100,80}` 会让最后一声永远响下去。

### ✅ 验证（Python 移植同一套逻辑，按 55 ms 主循环采样）
| 序列 | 实际时间线 | 结束电平 |
|---|---|---|
| 电压越限 | 响110 → 停110 → 响110 → 静音 | LOW / active=0 |
| 高温 | 响110 → 静音 | LOW / active=0 |
| 按键短按 | 响55 → 静音 | LOW / active=0 |
| 按键长按 | 响55 → 停110 → 响55 → 静音 | LOW / active=0 |

断言覆盖：四种序列都必须终止、结束必须回到 LOW、按键音中途被报警打断后也必须回到 LOW、每秒重复起播 5 次后电平始终为 LOW。时长偏差来自 55 ms 采样量化（100 → 110 ms），蜂鸣器听感无差别。

### 📦 占用
Keil AC5：0 Error / 3 Warning（原有 `#870-D`），Code 19072 B，RAM 3584 B（含 2 KB 显存）/ 20 KB。

### 📌 仍存在的阻塞（评估后保留）
`Motor_Forward()` 软启动每步 `HAL_Delay(25)`，0→70% 共 6 步 = **150 ms**。但它只在风扇启动那一次发生，属于一次性事件，画面"卡"150 ms 不可感知；改成状态机会动到电机时序，风险大于收益，**暂不改**。

## [3.0.2] - 2026-11-14

> 改掉 OLED 闪烁的真根源：**每帧真的把整屏写黑一遍**。上一版把刷新频率从 1 Hz 提到 10 Hz，结果黑闪从「每秒一次」变成「持续抖动」——方向本身就错了，刷新越快越难看。

### 🐛 修复
- **`oled.c` 改为「显存 + 差异刷新」**：新增 `g_ram[8][128]`（这一帧要显示什么）和 `g_on[8][128]`（屏幕上现在是什么），共 2 KB RAM。`OLED_Clear()` / `OLED_ShowString()` / `OLED_ShowCN()` 全部只写 RAM，一个字节 I2C 都不发
- **新增 `OLED_Refresh()`**：逐页找出与屏幕内容不同的第一列和最后一列，只发这一段连续区间；整页没变就直接跳过。屏幕任何时刻都不会出现黑屏
- **`OLED_SetPos()` 语义变更**：只移动 RAM 光标，不再发定位命令；真正发命令的搬到内部 `OLED_PosCmd()`
- **`OLED_Init()` 里把 `g_on` 填 0xFF 再刷一次**，强制首帧整屏建立（否则 BSS 全 0 会和实际"看起来一样"，导致一个字都不发）
- **采样节拍改 `HAL_GetTick()` 1 秒判定**，删掉 `adc_sample_cnt`。一圈的真实长度随刷屏量变化（90 ms → 95 ms → 55 ms），"圈数折算"每改一次显示就失真一次

### 📊 实测意义（Python 移植同一套逻辑验证）
| 场景 | 每帧发送字节 | 耗时 |
|---|---|---|
| 上电首帧 | 1024 / 8 页 | 23 ms（一次性） |
| 只电压末位跳动 | 29 / 2 页 | **0.8 ms** |
| 电压+温度同时变 | 50 / 4 页 | 1.4 ms |
| 切换过压/欠压模拟 | 227 / 6 页 | 5.3 ms |
| 数值完全不变 | **0 / 0 页** | **0 ms** |
| 改前（每帧固定） | 1024+ | 47 ms（含 24.8 ms 全屏纯黑） |

### ✅ 验证
- 仿真断言：刷新后 `g_on == g_ram`（无漏画）；`12.48V → 8.00V` 无残影
- 显存反渲染成 PNG，与设计稿逐像素一致
- Keil AC5：0 Error / 3 Warning（原有 `#870-D`），Code 19068 B，RAM 3568 B（含 2 KB 显存）/ 20 KB

## [3.0.1] - 2026-11-14

> 修复 K1（过压/欠压模拟键）"重启后短按长按都没反应、要按住很久才响应"。根因是按键状态机拿**循环圈数**当时间，而主循环一圈实际 94 ms 而不是 50 ms。

### 🐛 修复
- **按键时间基准改为 `HAL_GetTick()` 毫秒制**。主循环一圈 = `HAL_Delay(50)` + OLED 全屏刷新约 44 ms（8 页 × 129 B 清屏 + 约 800 B 文字，400 kHz I2C），即 94 ms。上一版按 50 ms 折算，所有时间被放大 1.9 倍：消抖 10 格 = 940 ms（设计 500 ms），长按 60 格 = 5.6 s，加上消抖要 **6.5 s** 才响应
- **消抖窗口 500 ms → 30 ms**：原来一次 150~300 ms 的正常点按根本过不了消抖，什么都不会发生
- **K1 去掉 1~3 s 静默死区**（`KEY_SHORT_MAX_K1` 1000 → 2999）：人检验按键习惯按 1.5~2.5 s，正好全落在这条缝里；现在任何一次按压都有结果，< 3 s 过压、≥ 3 s 欠压
- **开机 1 秒盲区**：原来 `OLED_Init()` 之后连着两次 `HAL_Delay(500)`，这 1 秒内 `Key_Scan()` 一次都不跑，按下的键全被吞掉。改为 10 × (Key_Scan + 50 ms)，开机画面期间按键照常生效
- **3.0 s 边界漏判**：长按只在"仍按住"的采样点触发，采样周期 90 ms 时按住整 3 s 可能正好跨过采样点。现在松手时补判一次 `held ≥ long_ms`
- **新增 `armed` 标志**：上电必须先读到一次"松开"电平才认按下，防止引脚极性配错或上电被拉高时凭空连发事件

### ✅ 验证
- 时序仿真（按 94 ms 采样，100~6000 ms 共 60 档）：每档恰好产生一个事件，无空档
- Keil AC5 编译：0 Error / 3 Warning（均为原有中文 printf 的 `#870-D` 编码提示）
- 占用：Code 18904 B，Flash 约 22.7 KB / 64 KB

### 🔍 顺带核实
- 核心板原理图第 5 页「按键」：`PA0 —[R8 1K]—+—[SW1]— 3V3`，`4.7K` 下拉到 GND —— **高电平有效**，与 `GPIO_PULLDOWN` + `== GPIO_PIN_SET` 一致，**不需要改极性**（项目内 10-21 那份《引脚冲突核查》里"按键另一端接地"的说法有误）

## [3.0.0] - 2026-11-14

> OLED 界面全中文化，同时把 WiFi 从「只发不收」补成双向心跳 —— 屏幕上的「无线通/无线发」从此是可被证伪的真状态。

### ✨ 新增功能
- **16×16 中文字模**：自带 38 字点阵（`Core/Inc/oled_cn_font.h`），宋体 15 px 渲染、二值化阈值 110，每字 32 字节（上/下半各 16 字节，列优先、bit0 在页顶，与 SSD1306 page 寻址直接对应）
- **中文显示接口**：`OLED_ShowCN()` / `OLED_ShowCNStr(y, x, n, ...)`，变参调用，`OLED_ShowCNStr(0, 0, 2, CN_DIAN, CN_CHI)` 即显示「电池」
- **WiFi 链路心跳**：ESP8266 每收到一帧回 `PONG\n`；STM32 开 USART3 接收中断，只认首字符 `'P'`，6 秒窗口内收到过才显示「无线通」，否则显示「无线发」
- **报警细分为三种**：`Alarm_t` 由原来的 1/2 拆成 `ALARM_OVP` / `ALARM_UVP` / `ALARM_TEMP`，屏幕能区分过压还是欠压

### 🔄 界面变更（128×64 → 4 行 × 16 px）
| 行 | 内容 |
|---|---|
| 1 | 电池 12.48V |
| 2 | 温度 25.3C |
| 3 | 风扇 低速 40% |
| 4 | 系统正常 无线通 |

- 数值统一右对齐到 `x = 124`，三行小数点排成一列
- 第 4 行状态词优先级：**模拟标记 > 实际报警 > 正常**，即过压模拟时显示「过压模拟」而不是「过压报警」——第一行本来就会跳到 13.50 V，得让人一眼分清是按键造的还是电池真出问题
- 报警不再单独占一行：改中文后一行吃 2 页、整屏只剩 4 行，报警并入第 4 行状态词
- 停机页改为「系统已停 / 请断电重启」

### 🐛 修复
- **8×16 ASCII 字库只有 16 个字符**（`' '` 到 `'/'`），而 `OLED_ShowChar` 按 `c = ch - ' '` 索引，显示 `'B'(0x42)` 时算出 34，早就越界读到别的常量了。之前没暴露，是因为界面清一色用 6×8 小字、这条分支一次都没被真正走过。现换成 `g_ascii8x16[95][16]`（0x20~0x7E 全 ASCII），并加了越界保护
- **`stm32f1xx_it.c` 里没有 `USART3_IRQHandler`**：启动文件给的是 weak 默认实现（`B .` 死循环），不自己覆盖，一开接收中断就会卡死。已在 `main.c` 定义

### 🔌 接线变更
- **J6-4 现在要接**：`J6-4 (RX) → NodeMCU TX`。这根线上只有 ESP8266 的 TX 一个输出（另两个是 CH340 的 RXD 和 STM32 的 PB11，都是输入），所以**烧录时不必拔 J6-4**；`J6-3` 仍然要拔（CH340 TXD 与 PB10 推挽对打）

- Keil AC5：**0 Error**，`Code = 18896`、`RO-data = 3772`、`RW-data = 72`、`ZI-data = 1440`
- Flash 22.2 KB / 64 KB（35%），RAM 1.5 KB / 20 KB（7.5%）
- ESP8266：Flash 271264 / 1048576（25%），RAM 38%，IRAM 91%

### ⚠️ 已知限制
- 只带 38 个汉字，**不做整字库**：GB2312 一级字 3755 × 32 字节 = 117 KB，塞不进 64 KB Flash。加字必须改生成脚本里的 `CN_STR` 重新生成，并把 `oled.h` 里 `CnChar_t` 枚举同步成一样的顺序，只改一边会显示成别的字
- 中文 15 px 而非 16 px：16 px 字模上下占满、四行之间零间隙，15 px 换来每行 2 px 行距

## [2.1.0] - 2026-10-23

> PCB 版打样下单后，固件由面包板验证版的引脚配置迁移到 PCB 版，并升级温度换算方式。

### 🔄 适配与变更
- **引脚迁移**：ADC 由 IN0/IN1（PA0/PA1）改为 **IN4/IN5（PA4/PA5）**；TB6612 的 AIN1/AIN2/STBY 由 PA2/PA3/PA8 改为 **PB12/PB13/PB14**，端口由 GPIOA 改为 GPIOB
- **PWMA 不变**：仍在 PA6（TIM3_CH1）
- **NTC 换算升级**：由「25 ℃ 对应 1.65 V」的线性估算改为 **B 值法**，`R_ntc = R3 × V ÷ (3.3 − V)`，`1/T = 1/T0 + ln(R/R0) ÷ B`，其中 `R3 = 10 kΩ`、`R0 = 10 kΩ`、`B = 3950`、`T0 = 298.15 K`

### ✨ 新增功能
- **探头故障判定**：ADC > 4040 判开路、< 15 判短路，以 −99 / −98 表示；OLED 显示 `NTC--`，串口打印 `NTC-- (open|short)`
- **故障安全策略**：探头异常时温控逻辑直接停风扇，不基于不可信温度做判断

### 🔒 安全性
- **禁用电机反转**：`Motor_Backward()` 改为空实现（等同 `Motor_Stop()`）。设计文档对 D2 型号记载不一致（§2.2 记 SMBJ15CA 双向 TVS，§8.2 记 SS34 单向肖特基并称反转会短路），实物核对前按最坏情况处理

### 🔧 问题修复
- 修复 `fan_status == 99` 时 OLED 误显示为 `High 100%` 的问题，改为 ` -- ` 占位

### 🗂️ 工程维护
- `LYC1.ioc` 更名为 `LYC1.ioc.bak`：该文件早已与代码脱节（仅单通道 ADC，缺 I2C1 / TIM3 / DMA / 按键配置），在 CubeMX 中点「生成代码」会把现有驱动全部冲掉

### ✅ 验证
- Keil AC6 编译：**0 Error**，`Code = 16424`、`RO-data = 1208`、`RW-data = 48`、`ZI-data = 1368`
- Flash 占用约 27%（64 KB），RAM 约 7%（20 KB）

### ⚠️ 待实物验证
- `divider_k = 6.21` 为面包板实测值，新板电阻批次不同需复校
- NTC 探头必须为 B = 3950（非 3435），否则全量程偏移
- D2 实物丝印确认：SS34 还是 SMBJ15CA
