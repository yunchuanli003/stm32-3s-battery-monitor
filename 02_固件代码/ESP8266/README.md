# ESP8266 联网与手机端页面

目标：ESP8266 作为"数据搬运工"，把 STM32 从 USART3 发来的 JSON 帧转成网页，
手机连同一 WiFi 直接浏览器查看。**不需要服务器、不需要域名、不需要备案。**

---

## 〇、买什么（结论）

| 用途 | 型号 | 说明 |
|---|---|---|
| 开发调试（先买这个） | **ESP8266 NodeMCU，CH340 USB 版** | 板载 USB 转串口，下载和看日志一根线搞定 |
| 最终装板（可选） | ESP-01S + 2×4 转接板 | 体积小，但只有 8 个脚、无 USB |

**不要只买 ESP-01S 裸模块**——它没有 USB 转串口，到手无法烧录，还要另配 USB-TTL 模块。

选 ESP8266 而不是 ESP32 的理由：本项目只需要 WiFi 上报，不需要 BLE 与双核算力；ESP8266 便宜、资料最多、AT 与 Arduino 生态都成熟。将来真要蓝牙，J6 是通用 1×6，换模块不用改板。

## 三、接口约定

页面每秒请求一次 `GET /api/data`，返回：

```json
{"v":12.35,"t":28.5,"fan":1,"alarm":0,"sim":0,"ts":123}
```

| 字段 | 含义 | 取值 |
|---|---|---|
| `v` | 电池总电压 | V，两位小数 |
| `t` | 温度 | ℃，一位小数 |
| `fan` | 风扇档位 | 0 停止 / 1 低速 / 2 高速 |
| `alarm` | 报警 | 0 正常 / 1 过压(>12.6V) / 2 欠压(<9.0V) |
| `sim` | 温度模拟模式 | 0 / 1 |
| `ts` | 上电秒数 | 用于判断数据是否卡死 |

## 四、上板时的接线与要点

| STM32 | ESP8266 | 说明 |
|---|---|---|
| PB10 (USART3_TX) | RX | 交叉连接 |
| PB11 (USART3_RX) | TX | 可暂不接（单向够用） |
| 3.3 V（独立 LDO，U3） | VCC | **不要用核心板的 3.3V**，见 PCB 设计输入 11.2 |
| GND | GND | 必须共地 |
| — | CH_PD / EN | 10 kΩ 上拉到 3.3 V |

固件侧还要做的两件事：

1. 用 STM32CubeMX 勾选 **USART3**（异步、115200、PB10/PB11），重新生成代码
2. 把 `WIFI_SendDataFrame(&huart1, ...)` 改成 `&huart3`（只有这一处）

## 五、ESP8266 固件要做的三件事

```
上电 → 连 WiFi（STA 模式）→ 起 HTTP 服务（80 端口）
                              ├─ GET /          → 返回 web/index.html
                              └─ GET /api/data  → 返回最近一帧 JSON
同时：串口整行读取，收到 '{' 开头的行就更新缓存
```

两个容易踩的点：

- **串口占用**：ESP8266 的 UART0 既是下载口也是调试口。如果直接拿来接 STM32，
  就看不到调试日志了。建议用 `Serial.swap()` 把 UART0 挪到 GPIO13/15，
  GPIO1/3 留给 USB 调试；具体以到货模块的板型为准。
- **断流保护**：超过 3 秒没收到新帧，`/api/data` 应该返回上一帧并在 `ts` 上体现，
  否则页面会拿着旧数据当实时值显示。

## 六、页面文件怎么进 ESP8266

`index.html` 只有约 7 KB，两种放法：

1. **PROGMEM 内嵌**：转成 `.h` 里的字符串常量，`server.send_P()` 直接发，最省事
2. **LittleFS**：文件放分区里，改页面不用重新编译，但要装上传插件

第一版推荐 PROGMEM 内嵌，改动少。
