# 串口发送完成确认修复计划

## 问题描述

KEY2长按触发系统停止时，"系统已经停止"的串口信息没有立即发送，而是等到系统开启时与"系统已经开启"的信息一起发送。

## 根因分析

1. 当前代码仅使用 `HAL_Delay(50)` 简单延时，不能保证串口数据真正发送完成
2. 蜂鸣器反馈的 `HAL_Delay(100)` 在 `system_running = 0` 之后执行，可能干扰发送
3. 缺少对串口发送完成状态的硬件检查

## 解决方案

### 方案：添加串口发送完成确认函数

1. 创建 `UART_WaitTxComplete()` 函数，检查 USART TC (Transmission Complete) 标志位
2. 调整执行顺序：先打印信息 → 等待发送完成 → 再改变系统状态 → 最后执行蜂鸣器反馈
3. 增加超时保护，防止无限等待

### 修改内容

| 文件 | 修改点 |
|------|--------|
| main.c | 添加 UART_WaitTxComplete() 函数 |
| main.c | 调整长按停止逻辑顺序 |
| main.c | 调整短按开启逻辑顺序 |

## 实现步骤

### 步骤1：添加串口发送完成等待函数

```c
// 等待串口发送完成（带超时保护）
void UART_WaitTxComplete(UART_HandleTypeDef *huart, uint32_t timeout)
{
  uint32_t tickstart = HAL_GetTick();
  while(__HAL_UART_GET_FLAG(huart, UART_FLAG_TC) == RESET)
  {
    if((HAL_GetTick() - tickstart) > timeout)
    {
      break;  // 超时退出，防止卡死
    }
  }
}
```

### 步骤2：调整长按停止逻辑

```c
// 长按触发：系统停止
key2_long_triggered = 1;
if(system_running == 1)
{
  // 1. 先打印信息
  printf("\r\n[系统] 系统已经停止\r\n");
  // 2. 等待串口发送完成（最多等200ms）
  UART_WaitTxComplete(&huart1, 200);
  // 3. 关闭LED和蜂鸣器
  HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_RESET);
  HAL_GPIO_WritePin(BEEP_GPIO_Port, BEEP_Pin, GPIO_PIN_RESET);
  // 4. 再改变系统状态
  system_running = 0;
  // 5. 最后蜂鸣器反馈
  HAL_GPIO_WritePin(BEEP_GPIO_Port, BEEP_Pin, GPIO_PIN_SET);
  HAL_Delay(100);
  HAL_GPIO_WritePin(BEEP_GPIO_Port, BEEP_Pin, GPIO_PIN_RESET);
}
```

### 步骤3：调整短按开启逻辑

```c
// 短按触发：系统开启
if(system_running == 0)
{
  // 1. 先打印信息
  printf("\r\n[系统] 系统已经开启\r\n");
  // 2. 等待串口发送完成（最多等200ms）
  UART_WaitTxComplete(&huart1, 200);
  // 3. 再改变系统状态
  system_running = 1;
  // 4. 最后蜂鸣器反馈
  HAL_GPIO_WritePin(BEEP_GPIO_Port, BEEP_Pin, GPIO_PIN_SET);
  HAL_Delay(50);
  HAL_GPIO_WritePin(BEEP_GPIO_Port, BEEP_Pin, GPIO_PIN_RESET);
}
```

## 风险评估

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| 超时时间不合适 | 发送不完整或等待太久 | 设置200ms合理超时 |
| 标志位检查不正确 | 还是等不到发送完成 | 使用 HAL 库提供的标准宏 |

## 验证方法

1. 烧录代码后，长按KEY2 3秒
2. 观察串口是否立即打印"[系统] 系统已经停止"
3. 短按KEY2，观察串口是否立即打印"[系统] 系统已经开启"
4. 两条信息应该分别在各自的操作后立即显示，不应该延迟到下次操作才一起显示
