# 项目问题记录与解决方案

本文档记录项目开发过程中遇到的问题、原因分析、解决方案和最终结果。

---

## 问题1：电阻过小，面包板操作复杂

### 问题描述
- 分压电阻阻值过小，在面包板上接线操作困难
- 影响电路搭建效率和稳定性

### 原因分析
- 初始选用的电阻阻值不适合面包板操作
- 电阻尺寸或引脚布局不便于插拔

### 解决方案
1. 更换适宜大小的电阻，简化操作
2. 选择引脚长度适中的电阻

### 解决结果
- 更换电阻后操作简化，问题解决

---

## 问题2：电阻引脚过长易短路

### 问题描述
- 电阻引脚过长，插入面包板时裸露引脚容易与其他部件接触
- 可能造成电路短路，导致实验失败或器件损坏

### 原因分析
- 电阻引脚预留过长
- 面包板空间有限，元件密集排列时容易发生接触

### 解决方案
1. 剪短电阻引脚
2. 错位插入，避免引脚靠近

### 解决结果
- 引脚处理后未再发生短路问题

---

## 问题3：下载程序后LED不亮，串口无显示

### 问题描述
- 程序下载成功后，LED指示灯不亮
- 打开串口调试后，无法正常显示实验结果
- 系统看起来没有正常运行

### 原因分析
#### 原因1：GPIO配置错误
- STM32CubeMX中GPIO输出设置不正确
- PA1、PA2设置为不上拉不下拉
- PB0引脚未开启

#### 原因2：变量定义位置问题
- `float adc_pin_voltage` 变量定义在 `while(1)` 循环最里面
- 老版本Keil编译器对这种写法支持不好
- 可能导致变量初始化或内存分配问题

### 解决方案
1. **修正GPIO配置**
   - 将PA1、PA2正确设置为上拉模式
   - 开启PB0引脚

2. **修改变量定义位置**
   - 将 `float adc_pin_voltage` 变量移到 `while(1)` 循环外面定义
   - 确保编译器能正确处理变量

### 解决结果
- 修正GPIO配置和变量位置后
- LED正常点亮
- 串口数据正常显示
- 问题完全解决

---

## 问题4：面包板接线杂乱

### 问题描述
- 面包板上的接线杂乱无章
- 不易区分电路连接关系
- 增加排查故障难度
- 容易造成电路短路

### 原因分析
- 接线时没有规划走线
- 导线颜色未区分功能
- 元件位置随意摆放

### 解决方案
1. **颜色区分**
   - 火线全部使用红色导线
   - 零线全部使用青色导线
   - 方便区分零火线

2. **区域划分**
   - 面包板划分三个区域
   - 核心板区域
   - 电阻区域
   - 功能器件区域
   - 对应元件安置在对应区域

3. **走线规划**
   - 导线尽量不叠加
   - 走线需要规划且规整
   - 避免跨区域杂乱走线

### 解决结果
- 接线整齐有序
- 电路可读性大幅提升
- 排查故障效率提高
- 未再发生接线导致的短路问题

## 问题5：电压测量误差过大

### 问题描述
- 串口打印的电压数据与实际电压误差过大
- 测量值与万用表实测值偏差明显
- 影响监测系统的准确性

### 原因分析
- 初始分压系数设置不准确
- `divider_k = 5.15f` 与实际硬件不匹配
- 电阻精度、连线压降等因素导致理论值与实际值有偏差

### 解决方案
1. **实测基准电压**
   - 断开监测对象正负极
   - 使用万用表直流20V档测量电池实际电压
   - 记录精确数值

2. **记录初始误差**
   - 打开串口调试软件
   - 记录当前显示的电压值

3. **校准分压系数**
   - 根据比例关系计算新系数
   - 公式：新系数 = 当前系数 × (目标电压 / 当前显示电压)
   - 由于系数和显示电压成正比，直接用实测值换算
   - 将 `divider_k = 5.15f` 更改为 `divider_k = 6.21f`

4. **验证校准结果**
   - 重新接入电池正负极
   - 烧录程序验证

### 解决结果
- 校准后串口打印数据与实际电压
- 误差减小到 **0.02V及以内**
- 测量精度满足要求

## 问题6：KEY2第二次长按不打印停止信息

### 问题描述
- 第一次长按KEY2，成功打印"系统已经停止"，系统正常停止
- 短按KEY2开启系统后，再次长按KEY2，系统直接停止但**不打印停止信息**
- 再次短按KEY2时，**先打印延迟的"系统已经停止"，再打印"系统已经开启"**
- 停止信息被延迟到下一次短按才显示

### 原因分析
#### 根因：状态标志设置条件不正确
- 代码中 `key2_long_triggered = 1` 只在 `system_running == 1` 时设置
- 当系统已经停止时（`system_running == 0`），再次长按KEY2：
  1. 长按计时达到60（3秒）
  2. 进入 `else if(key2_long_triggered == 0)` 判断
  3. 但因为 `system_running == 0`，不执行停止操作
  4. **关键问题**：`key2_long_triggered` 仍然是 `0`！
- 按键释放时，因为 `key2_long_triggered == 0`，误判为"短按"
- 但此时系统已停止，短按不会触发开启操作
- 等到真正短按开启时，之前被缓存的停止信息才被发送

```c
// 错误的代码逻辑（问题所在）
else if(key2_long_triggered == 0)
{
  if(system_running == 1)
  {
    key2_long_triggered = 1;  // ← 只在系统运行时设置
    // 执行停止操作...
  }
  // 当 system_running == 0 时，key2_long_triggered 仍然是 0！
}
```

### 解决方案
**将长按标志设置移到条件判断外面**，确保无论系统状态如何，只要达到长按时间就设置标志：

```c
// 修正后的代码逻辑
else if(key2_long_triggered == 0)
{
  key2_long_triggered = 1;  // ← 无论系统状态如何，都设置长按标志
  
  if(system_running == 1)
  {
    // 只在系统运行时执行停止操作...
  }
}
```

**修改位置**：`02_固件代码/STM32F103C8T6/LYC1/Core/Src/main.c` 第 121-143 行

### 解决结果
- 第二次长按KEY2时，即使系统已停止，也会正确设置长按标志
- 释放按键时不会误判为短按
- 停止信息立即打印，不会延迟到下一次操作
- 状态同步问题完全解决

## 问题7：电机不转或输出异常（最容易踩的坑！）

### 问题描述
- TB6612电机驱动模块输出异常
- STM32发送了控制信号，但电机毫无反应
- 电机时转时不转，行为诡异
- 电机能转但转速异常、无力或抖动
- 卡了两天都找不到原因

### 原因分析
#### 根本原因：**没有共地！** 这是TB6612第二常见的坑！

**具体原因：**
1. **江科大面包板套件的电源轨是**左右分开**的（和野火小智套件不一样！
2. 面包板左右两边的电源轨不连通
3. STM32的GND、TB6612的GND、电池的GND三者没有真正连接在一起
4. 逻辑电平参考不一致，导致TB6612无法正确识别STM32的控制信号
5. 误以为插在面包板上就共地了，实际上根本没有连通

### 解决方案
#### 必须保证三者共地：

1. **面包板电源轨连通**
   - 用导线连接面包板左右电源轨
   - 江科大套件：左右电源轨必须用导线跨接！

2. **三点共地（最保险）：
   ```
   STM32的GND
        ↓
   TB6612的GND
        ↓
   电池的GND（电源负极）
   ```

3. **操作步骤：**
   - 用一根杜邦线直接连接：STM32 GND ↔ TB6612 GND
   - 用一根杜邦线直接连接：TB6612 GND ↔ 电池GND
   - **不要依赖面包板电源轨！** 最好用杜邦线直接跨接三个GND点

### 解决结果
- 共地后电机立即正常工作
- 控制信号正常传递
- 电机转速、方向控制正常
- 问题完全解决
