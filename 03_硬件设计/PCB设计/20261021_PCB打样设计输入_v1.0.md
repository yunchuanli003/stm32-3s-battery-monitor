# PCB 打样设计输入（第一版）

> 目标：把现有面包板方案转成一块可打样的 2 层板，功能与 v2.0 固件保持一致
> 工具：立创EDA（专业版）
> 状态：设计输入，尚未开始原理图

---

## 〇、三个前提（需要你确认，不同意就改）

| 前提 | 选择 | 理由 |
|---|---|---|
| MCU 形态 | **沿用现成核心板**，用 2×20 排母插装 | 核心板自带晶振、复位、USB、3.3V LDO，省掉最容易翻车的部分；第一次打样不值得冒这个险 |
| 电机驱动 | **TB6612 模块**，2×8 排母插装 | FNG 芯片是 SSOP-24，手工焊接成功率低；模块几块钱，坏了直接换 |
| 降压 | **MP1584EN 模块** | 输入 4.5–28 V、3 A，可调输出，免去 Buck 外围布局和补偿设计 |

> 这套思路叫"模块化降风险"：把不可控的环节（焊接、开关电源布局）交给成熟模块，自己只画可控的部分（接口、采样、保护、指示）。
> 面试时这是加分点，不是减分点——能说清"为什么第一版不集成"，比画得花哨更显工程判断。

## 一、电源架构（最关键的一节）

```
3S 电池 9.0–12.6 V
   │
   ├─ 保险丝 1.5 A → 防反接 SS34 → ├─ Buck(MP1584) → 5 V ─┬─ 核心板 5V 引脚（板载 LDO 再降 3.3 V）
   │                              │                      ├─ 蜂鸣器（有源 5 V）
   │                              │                      └─ U3 AMS1117-3.3 → +3V3_WIFI（WiFi 专用，见 11.2）
   │                              └─ TB6612 VM（12.6 V 直供）→ 130 电机
   └─ GND
```

**为什么不是 12.6 V 直接降到 3.3 V**

AMS1117 类是线性稳压，压差全变成热。12.6 V → 3.3 V、负载 70 mA，功耗 ≈ 0.65 W，SOT-223 封装结温会逼近 125 ℃ 触发过温保护，表现为输出电压跌落、MCU 反复复位。这类故障极难从软件侧定位。

**为什么走 5 V 再进核心板**

核心板板载 LDO 吃 5 V 只需降 1.7 V，功耗约 0.12 W，安全。这样整块板只做一级 Buck，架构最简单。

**必须加的元件**

| 位置 | 元件 | 作用 |
|---|---|---|
| 电池入口 | 自恢复保险丝 1.5 A（如 MF-MSMF150） | 短路保护 |
| 电池入口 | SS34 肖特基（SMA 封装） | 防反接；正常压降 0.5 V，12.6 → 12.1 V，可接受 |
| Buck 输入 | 100 µF/25 V 电解 + 0.1 µF 陶瓷 | 抑制电池线束电感引起的输入纹波 |
| Buck 输出 5 V | 22 µF + 0.1 µF | 输出储能与高频去耦 |
| TB6612 VM | 100 µF/25 V 电解 + 0.1 µF，**紧贴模块 VM 与 GND 引脚** | 电机换向瞬间的电流尖峰靠它吸收 |
| 电机端子 | 0.1 µF 跨接电机两端 + 双向 TVS（SMBJ15CA） | 换向反电动势泄放 |

## 二、模拟采样电路

### 2.1 电压采样

| 项 | 取值 |
|---|---|
| 上臂 R1 | 51 kΩ，1%，0805 |
| 下臂 R2 | 10 kΩ，1%，0805 |
| 分压比 | (51+10)/10 = **6.10** |
| 12.6 V 时分压点电压 | 2.07 V（ADC 满量程 3.3 V，余量充足） |
| 源阻抗 | 51k ∥ 10k ≈ **8.4 kΩ**（STM32F1 在 239.5 周期采样下允许约 50 kΩ，安全） |
| 滤波 | 分压点对地 **100 nF**（X7R，0603），走线尽量短，紧贴 PA4 |
| 分辨率 | 3.3 V / 4095 ≈ 0.806 mV，折算到电池端约 **4.9 mV** |

> 换 1% 电阻后，固件里的 `divider_k = 6.21f` 需要按实测重新标定一次（原值来自旧电阻的实际误差）。
> 标定方法沿用你原来的：万用表实测电池电压 → `新系数 = 旧系数 × 实测值 / 显示值`。

### 2.2 温度采样

| 项 | 取值 |
|---|---|
| NTC | 10 kΩ，B=3950，1% |
| 上拉 | 10 kΩ，1%，接 3.3 V |
| 接法 | **NTC 在下臂**（NTC 到 GND，上拉电阻到 3.3 V） |
| 25 ℃ 时分压点 | 1.65 V |

**接法必须保持 NTC 在下臂**，这样温度升高 → NTC 阻值下降 → 分压点电压下降，与现有固件 `temperature = 25.0f + (1.65f - temp_volt) * 15.0f` 的方向一致，改板不用改代码。

**但这条公式建议重写。** 10 k/B3950 在 25 ℃ 附近灵敏度约 4 %/℃，换算成电压约 25~27 ℃/V，而当前用 15 ℃/V，斜率只有实际的一半左右。粗算下来：

| 实际温度 | 分压点电压 | 当前公式读数 | 偏差 |
|---|---|---|---|
| 25 ℃ | 1.65 V | 25.0 ℃ | 0 |
| 28 ℃ | 1.57 V | 26.2 ℃ | −1.8 ℃ |
| 32 ℃ | 1.48 V | 27.5 ℃ | −4.5 ℃ |
| 35 ℃ | 1.42 V | 28.4 ℃ | −6.6 ℃ |

温度越高偏差越大，而风扇的两个阈值（28 ℃、32 ℃）正落在这段区间。**打样顺手把温控改准，是这个项目最划算的一次改进**——硬件不用动，只换固件里的换算方式（查表或 Steinhart-Hart），误差能从数度降到 0.5 ℃ 内。

### 2.3 按键

10 kΩ 上拉到 3.3 V，并联 100 nF 做硬件消抖，再进 PC13。软件里的 10 次计数消抖可以保留，也可以减到 3 次。

## 五、布局约束（先摆位，再拉线）

板子建议 **100 × 80 mm 以内**，四角 M3 安装孔。

| 区域 | 位置 | 放什么 |
|---|---|---|
| 电源区 | 左侧，靠近电池端子 | J1、F1、D1、C1、Buck 模块、C3 |
| 功率区 | 右下，靠近电机端子 | TB6612 模块、C2、J2、D2 |
| 模拟区 | 中部偏上 | R1、R2、R3、RN1、C11 ×2 |
| 数字区 | 中部 | U1（核心板）、SW1、OLED、LED、蜂鸣器 |
| **扩展预留区** | 右上角，贴板边 | WiFi/BLE 模块排针位（J6）+ 天线净空带 |

四条硬约束：

1. **ADC 滤波电容紧贴 PA4 / PA5 引脚**，中间不串过孔，走线长度控制在 5 mm 内
2. **TB6612 的 100 µF 电解必须紧贴模块 VM 与 GND 引脚**，走线宽度 ≥ 1 mm
3. **电机大电流回路（VM → TB6612 → 电机 → GND）面积越小越好**，不要绕板子一圈
4. **右上角沿板边留 30 × 20 mm 空区**，且该区域正对的天线净空带内**不铺铜、不走线、不放器件**（详见第十一节）

接地策略：底层整块铺 GND 不切碎；功率地与信号地在电池端子处单点汇合，不要在两处相连形成环路。

## 九、立创EDA 操作顺序（版本不同菜单名可能微差）

1. 新建工程 → 建原理图
2. 在"元件库"搜标准件（电阻、电容、三极管、端子、排母），模块用"多引脚排母"代替
3. 按第四节网络表连线，标注网络名（画网络标签比拉长线清晰）
4. 原理图 → **设计管理器 / 校验**，确认无未连接引脚
5. 转 PCB，先画板框（100×80），放 4 个 M3 孔
6. 按第五节分区摆放，先放连接器和模块，再放小元件
7. 设规则：线宽、间距、过孔尺寸按第六节
8. 布线 → 铺铜（底层整块 GND）→ 丝印调整
9. DRC → 按第八节逐条过
10. 导出 Gerber + BOM + 坐标文件，上传嘉立创下单

## 十、封装与可焊性（打完能不能直接插上、焊上）

先纠正一个常见误解：**3D 预览不生成任何制造数据。**

工厂拿到的是 **Gerber（各层铜箔 / 阻焊 / 丝印）+ 钻孔文件 + BOM**。3D 只是给你自己检查"元件会不会打架"用的，它不参与生产。所以"把 3D 转给工厂打样"这个理解不成立。

要保证打回来能直接装，只有一件事：**原理图里每个器件的封装，必须和你要买的实物一一对应。** 立创EDA 里一个器件由三部分组成：

| 组成 | 作用 | 出错后果 |
|---|---|---|
| 符号 Symbol | 原理图上的图形与引脚 | 引脚数与实物不符，连错网络 |
| 封装 Footprint | PCB 上的焊盘尺寸与间距 | **打完焊不上**，最致命 |
| 立创编号 | 对应商城里具体物料 | BOM 下错料 |

必须做的三个动作：

1. **优先用带商城编号的标准件**，BOM 能一键下单，避免自己建库建错
2. **转 PCB 前逐个确认都有封装**，没绑封装的器件转过去会消失或报错
3. **拿卡尺量一遍实物**，尤其模块——TB6612 有 2.54 和 2.0 两种排针间距，OLED 有直排和弯排

常见封装与孔径对照：

| 元件 | 封装 | 孔径 / 说明 |
|---|---|---|
| 0805 / 0603 贴片 | R0805、C0603 等 | 无孔径 |
| 直插电阻 | AXIAL-0.4 | 孔径 0.8 mm（引脚约 0.5 mm） |
| 3 mm LED | LED-3MM | 孔径 0.9 mm，注意长短脚 |
| 6×6 轻触按键 | SW-6x6x5 | 4 脚，孔径 0.9 mm |
| 2.54 排针 / 排母 | HDR-1x4、1x5 | 孔径 1.0 mm |
| KF301 端子 | KF301-2P | 孔径 1.3 mm |
| M3 安装孔 | — | 孔径 3.2 mm，非金属化 |

丝印必须标清：**位号（R1 / C1 / U1）+ 极性标记**（二极管横杠、电解电容负极、LED 方向、连接器 PIN1）。没有丝印，焊接时只能靠猜。

## 十一、扩展预留（WiFi / 蓝牙 / 手机 App）

**结论：会受影响，但影响可以提前消除。** 打板后再加模块，能补的只有"飞线 + 外挂"，补不回来的是三样：**引脚、电源、天线净空**。这三样现在留成本几乎为零，不留就只能改板重打。

### 11.1 引脚：别指望 USART2，它已经被占了

STM32F103C8T6 只有三路串口：

| 串口 | 引脚 | 现状 |
|---|---|---|
| USART1 | PA9 / PA10 | 已用于调试串口 |
| USART2 | PA2 / PA3 | **已被 TB6612 的 AIN1 / AIN2 占用，且 F103 的 USART2 不能重映射** |
| USART3 | PB10 / PB11 | **当前完全空闲，这就是 WiFi 模块该走的口** |

所以现在就把 **PB10 / PB11 引到 J6**（USART3）。这是唯一"不改硬件就能接无线模块"的路，这两个脚若空着不出板，打样后只能飞线。

J6 定义（1×6P，2.54 mm，ESP8266 与 ESP32 底板都通用）：

| 脚 | 网络 | 说明 |
|---|---|---|
| 1 | `+3V3_WIFI` | 独立 3.3 V |
| 2 | `GND` | |
| 3 | `USART3_TX` | 接模块 RX |
| 4 | `USART3_RX` | 接模块 TX |
| 5 | `WIFI_EN` | 复位 / 使能，10 kΩ 上拉 |
| 6 | `WIFI_IO0` | 烧录模式：拉低进下载，平时 10 kΩ 上拉 |

> 若想让 ESP-01S 直接插在板上，另加一组 **2×4 母座**即可，但**引脚顺序必须用万用表对照实物逐脚确认**（不同批次丝印方向不一致，插错会烧模块）。
> 第一版建议只用 1×6 排针 + 杜邦线接模块底板，零风险。

### 11.2 电源：必须独立，不能挂核心板的 LDO

ESP8266 发射瞬间电流可达 300 mA，ESP32 更高（约 500 mA）。核心板上那颗 AMS1117 是给 MCU 用的，余量小、去耦只有 10 µF 级。

若 WiFi 模块的 3.3 V 直接取核心板 3.3 V 引脚，模块一发射，电源被拉低 → **MCU 复位**。现象是"一连上 WiFi 就重启"，极容易被误判成程序 bug。

正确做法：板上单独放 **AMS1117-3.3（U3）从 5 V 转 3.3 V**，配 10 µF + 0.1 µF，专供 J6。成本几毛钱，省掉一整轮排查。

### 11.3 天线：物理不可逆，必须现在留

模块天线周围需要净空，下方不能铺铜、不能走线、不能放金属件，最好让天线正对板边或伸出板外。

**这一项打板时没留，后期无法补救**，只能锯板或把模块架空飞到板外。

本版安排：右上角 30 × 20 mm 空区放 J6，其正上方沿板边留 8~10 mm 净空带，铺铜时挖空。

### 11.4 模块方案对比

| 方案 | 优点 | 缺点 | 适合 |
|---|---|---|---|
| ESP8266（ESP-01S） | 便宜、资料多、AT 指令简单 | 仅 WiFi，烧录要单独接线 | 快速联网，两周出效果 |
| ESP32-WROOM | WiFi + BLE 双模、算力强 | 稍贵、功耗高、天线占位大 | 想同时讲 BLE 与云两条链路 |
| 蓝牙模块（HC-05/06） | 最简单，手机直连 | 仅近距离，不能上云 | 纯演示 |

手机端三条链路：

1. **局域网 TCP/UDP**：手机与模块同一 WiFi，App 直连 IP。最简单，但离开该网络就看不到
2. **MQTT 云平台**（巴法云、阿里云 IoT、EMQX）：设备发到云，App 订阅。**可远程查看，演示效果好，也好讲架构**
3. **BLE 直连**：适合 ESP32，手机读特征值。近距离、低延迟

对秋招推荐 **ESP8266 + MQTT** 或 **ESP32 + MQTT**：能讲清"STM32 采集控制 → ESP 联网 → 云端存储转发 → 手机 App 展示"的四层分工，比单纯说"加了个 WiFi"有价值得多。

### 11.5 一个务实建议

**WiFi 模块不要焊死**，用 1×6 排针插装（和 TB6612 同一思路）。理由：配网失败要反复烧录，插装可以拔下来用 USB-TTL 单独调试；将来换 ESP32 只换模块，不用改板。

另外，模块烧录需要 **USB-TTL 串口模块**（CH340 等）。第一版不建议把 CH340 画到板上——多一个芯片就多一个故障点，外接一根线更省事。

### 11.6 数据链路与通信协议

硬件只解决"能连"，App 能不能显示取决于**STM32 往外吐什么格式**。现在固件里 USART1 打的是给人看的调试文本：

```
Battery: 12.35V | Temp: 28.5C | V-ADC: 3245 | T-ADC: 2048
```

这种格式给 App 解析很痛苦。建议**新增一路面向机器的数据帧**，走 USART3 发给 WiFi 模块，用单行 JSON：

```json
{"v":12.35,"t":28.5,"fan":1,"alarm":0,"sim":0,"ts":12345}
```

| 字段 | 含义 |
|---|---|
| `v` | 电池电压（V，两位小数） |
| `t` | 温度（℃） |
| `fan` | 风扇档位：0 停 / 1 低速 / 2 高速 |
| `alarm` | 报警：0 正常 / 1 过压 / 2 欠压 |
| `sim` | 温度模拟模式：0 / 1 |
| `ts` | 上电后秒数，用于 App 判断数据是否新鲜 |

三件事要注意：

1. **波特率与模块一致**（建议 USART3 也用 115200）
2. **ESP8266 上电会先吐一堆乱码启动日志**（74880 或 115200 波特率），STM32 侧解析要做容错，不能一见非 JSON 就死等
3. **发送频率别太高**，1 Hz 足够；WiFi 发包太频繁会占 CPU、也增加功耗

App 侧拿数据的三种方式：

| 方式 | 实现 | 适用 |
|---|---|---|
| 局域网 HTTP | ESP8266 跑 Web Server，App 定时 GET `/api/data` | 同一 WiFi 下最简单 |
| 局域网 WebSocket | ESP 主动推送，App 实时刷新 | 想要秒级响应 |
| 云端 MQTT | ESP 发布到主题，App 订阅 | **可远程查看，推荐** |

**结论：只做"同一 WiFi 下看数据"，一个 ESP8266 就够了，不需要服务器。想要随时随地看，再加一个免费 MQTT 平台当中转，仍然不需要自己写服务器。**
